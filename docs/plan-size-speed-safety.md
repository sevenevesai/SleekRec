# SleekRec size, speed and safety plan

Orchestrated 2026-10-24. Goal: a smaller, lighter and safer SleekRec with no loss of recording
capability. Each item lands on main as its own verified commit or is descoped with the reason.
Workers read their section and do not edit this file; the orchestrator ticks items as they land.

## Baseline (1.1.2 build of 2026-09-17, `dist_app`)

- [ ] 4. Stop idle source polling (refresh on mount, focus and demand); overlay as a small static page keeping the IPC contract and 320 px width. Worker IDLE, branch `slim/idle`.
- [ ] 5. Trimmed FFmpeg 6.1.1 build with only the components the app and tests use, replacing the 79 MiB binary on Windows. Worker FFMPEG, branch `slim/ffmpeg`. Ships only if `SMOKE PASS` and a real capture run pass.

Merge order: CONFIG, HARDEN, IDLE, FFMPEG. Each later branch is rebased onto main after the one
before it lands. Known touch points: `package.json` (CONFIG, FFMPEG), `electron/main.ts`
webPreferences (HARDEN) and overlay creation (IDLE).

## Gates for every landing

`npx tsc --noEmit` clean; `npm test` with the test count not lower than before; `npm run
test:recording` prints `SMOKE PASS`; `npm run build:win` succeeds and the unpacked size is
recorded. Items 5 and 6 add a real capture run through the packaged app with the output file
checked by FFmpeg (duration above zero, video and audio streams present).

## Invariants

- Overlay visible behaviour and 320 px width are unchanged.
- Stop ordering in `docs/recording.md` is unchanged; breaking it truncates the final chunks.
- Masters and failed capture parts are preserved; compression stays a separate export.
- No release, version bump, publish or push. Landing is onto local main only.

## Out of scope

AMD/Intel GPU capture, export UX, hooks beyond the CI gates, removal of the FFmpeg 6.1
workarounds listed in `docs/recording.md`.
